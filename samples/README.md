## 補足

- **anthropics-pdf**: 対象スキルのソース（`source/`）は再配布しない。`provenance.json` の commit を `fetch_target.py` で取り直せば、同じ版を再現できる。
- **self-audit**: 監査時点のソース一式を `source/` に含めている（`tests/test_self_audit.py` がこのサンプルを検査する）。このとき指摘された次の点は、その後の版で修正した。
  - 最小指示の出所チェックが、どこにある README でも通ってしまう → スキル直下の README だけを認める
  - 「実証済みと書かない」の README 記述が、検査範囲（構造化ラベル）より強い → 記述を検査範囲に合わせた
  - テストコード中の文字列が欠落参照として大量に出る → 欠落参照は SKILL.md から辿れるファイル・スクリプト・README だけから数える
  - 目安字数と警告閾値の不一致、存在しない章への参照、未実装の Phase 3 の説明が毎回読み込まれる、description の「review」が通常のコードレビューでも発火しうる → 修正
  - 悪性フィクスチャが配布物に入る → インストール時は `tests/` を除く手順を README に明記
- 自己監査には構造的な限界がある。監査者のコンテキストには自分の SKILL.md が読み込まれているので、「本文を読む前に最小指示を書く」手順が守れない。この限界は監査エージェント自身がレポートの limitations に書いている。
