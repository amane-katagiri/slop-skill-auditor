## pdf スキル

価値の中心は、フォーム入力の手順と同梱スクリプト（欄情報の抽出、値の検証、座標変換、重なりの検査）にある。分量の大半を占める一般的な PDF 操作のコード例は、素のモデルでも書ける内容と判断している。「スキャンした PDF を検索可能にする」という説明には実装が足りないこと、フォーム手順の最初のコマンドに誤りがあることも指摘している。

対象スキルのソース（`source/`）は再配布しない。`provenance.json` の commit を `fetch_target.py` で取り直せば、同じ版を再現できる。

## 自己監査

取得、棚卸し、根拠の検査、実験の仕組みはコードで実装されていて短い指示では再現できないが、監査の判断の質そのものが短い指示より良くなるかは測られていない、という結論。

README との食い違いとして次の2点を指摘した。どちらも、この監査のあとの版で修正した。

- 隔離の自動確認が、スクリプトを含まずシェルも使わない実験では行われていなかった → どの実験でも事前に確認するようにした
- 「実証済みと書かない」をスクリプトで検査するという README の記述が、実際の検査範囲（判定ラベル）より強かった → 記述を検査範囲に合わせた

監査時点のソースを `source/` に含めている（`tests/test_self_audit.py` がこのサンプルを検査する）。

自己監査には構造的な限界がある。監査するエージェントのコンテキストには自分の SKILL.md が読み込まれているので、「本文を読む前に比較用の短い指示を書く」手順が守れない。
